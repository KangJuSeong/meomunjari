## 2. 차 안에서 해결할 문제

차박 경험률의 조사 연도를 명시하고 차량 기록을 쓰는 이유를 추가했다.

| v1 원문 | v2 수정본 |
|---|---|
| 왜 차 안에서 해결해야 하는가 (조사 필요)(린회) | 왜 차 안에서 해결해야 하는가 |
| 국내 숙박 캠핑 이용자는 2020년 기준 534만 명이고, 차박 이용률은 3.9%로 별도 유형을 이룰 만큼 자리 잡았다(한국관광공사 「2020년 기준 캠핑이용자 실태조사」). 차박은 차가 곧 숙소라서, 그 밤의 온도·전력 소모·날씨를 가장 정확히 아는 것도 차다. 지금까지는 이 데이터가 차 안에서 사라졌다. 머문자리는 차량 데이터를 스팟 정보로 바꿔, 사람이 쓴 후기의 한계를 객관적인 숫자로 보완한다. | 한국관광공사에 따르면 2021년 한 해 우리 국민의 4%가 차박을 경험했다. 차박에서는 차가 숙소다. 같은 장소라도 기온과 난방 시간에 따라 아침에 남는 배터리가 달라진다. 머문자리는 다녀간 차량의 기록을 다음 운전자의 출발 전 판단에 쓴다. |

## 3. 에너지 예측과 길안내

난방·대기 분리, 실측 2건 기준과 충전 경유 동작을 명시했다.

| v1 원문 | v2 수정본 |
|---|---|
| ② "내 차로 버틸 수 있나" 에너지 예측 | ② “내 차로 하룻밤 머물 수 있을까?” 에너지 예측 |
| 현재 잔량, 남은 경로 거리, 해당 스팟의 실측 소모율을 합쳐 "지금 62% → 도착 60% → 아침 46% · 충전소까지 충분해요"처럼 알려 준다. | 현재 배터리에서 차박지까지 주행에 쓸 양을 빼 도착 잔량을 구한다. 도착 후 8시간 동안 시간대별 기온이 10°C 미만이면 난방을 쓴다고 가정한다. 같은 스팟·같은 달의 전기차 기록으로 난방과 대기에 들 전력을 추정해 아침 잔량을 표시한다. |
| 빠듯하면 "경로상 충전소에서 15분 충전 후 출발"처럼 대안을 제안한다. 실측이 없는 스팟은 “측정중”으로 표시하며 2회 이상 리포트 등록 시, 에너지 예측을 표시해준다.(린회 조사 필요) | 유효한 전기차 기록이 0~1건이면 “측정중”, 2건이면 참고치로 표시한다. 아침 잔량이 인근 충전소까지 갈 전력과 여유분 15%p에 못 미치면 도달 가능한 경유 충전소와 충전 시간을 제안한다. 운전자가 선택하면 차박지를 최종 목적지로 유지한다. |
| "여기로 갈래요" 한 번으로 차량 내비 목적지를 설정한다. 주행 중(D·R단 또는 주행 속도)에는 화면을 숨기고, 남은 거리·시간·도착 시 예상 배터리 잔량을 표시해준다. | 운전자는 차박지로 바로 가거나 추천 충전소를 경유할 수 있다. 주행 중에는 남은 거리와 시간을 표시한다. 경유 경로에는 충전소 이름과 예상 충전 시간을 함께 표시한다. |

## 4. 시연 시나리오

고정된 예상 수치를 재현 가능한 시연 절차로 바꿨다.

| v1 원문 | v2 수정본 |
|---|---|
| [에너지 확인] 배터리 62%면 "아침 46% · 충분해요", 25%면 "경로상 충전소에서 15분 충전 후 출발"(주성)이 나온다. | [에너지 확인] 11월 속초에서 인제 방태산 계곡 쉼터를 선택한다. 가상 콘솔에서 배터리를 62%와 25%로 바꿔 아침 잔량과 충전 권고를 비교한다. 충전소 경유를 선택하고 최종 목적지를 확인한다. |
| [밤사이] 자는 동안 차가 내·외부 온도와 배터리 사용량을 기록한다. 출발 전 확인한 [에너지 확인]과 근사하게 아침에 배터리가 40%대임을 확인했다. | [밤사이] 차박 시작 후에는 현재 배터리와 공조 상태, 남은 시간으로 아침 잔량을 다시 계산한다. 차박을 마치면 처음 예측한 값과 실제 남은 배터리를 비교한다. |

## 5. 구현 범위와 검증

목업과 후속 실연동, SDK가 처리하는 동작과 앱이 추정하는 값을 구분했다.

| v1 원문 | v2 수정본 |
|---|---|
| NaviHelper SDK: requestRoute로 목적지 설정·취소, 남은 거리·시간 표시 | NaviHelper SDK로 직행·취소, 충전소 포함 경로 요청, 현재 안내 중인 차박지에 경유지 추가를 처리한다. 1차의 거리와 시간은 앱에서 추정한다. |
| 자체 백엔드: 스팟·검색, 방문 인증, 리뷰·태그, 실측 리포트 수집·집계, 에너지 예측, 뱃지 엔진의 6개 모듈과 DB·이미지 저장소 | 1차는 별도 서버 없이 스팟·야간 기온·충전소·리포트 예시 데이터를 앱에 넣고 계산한다. 기상청 단기예보의 시간대별 기온(TMP)과 실제 충전소 데이터는 후속 연동 대상으로 둔다. |
| 완료: 아키텍처·화면·기능 설계. 앱 화면 9종과 시연 시나리오 전체 흐름을 로컬 목 데이터 기반으로 구현했다. 도메인 로직 단위 테스트 17건이 통과했다. | 로컬 목업에서 아침 잔량 계산과 충전소 경유 시연을 구현했다. 자동 테스트로 표본 수, 기온에 따른 충전 권고 변화, 경유 후 차박지 도착을 확인한다. |
| 이후: 백엔드 6개 모듈을 구축해 목 데이터를 실서버로 교체하고, 금지 구역 공공데이터 연동, 위치 공개 범위 정책, 실제 일출 시각 보정 기록을 추가한다. | 이후에는 기상청 단기예보와 운영 중인 충전소·충전기 정보를 연결하고, 차량별 예측 오차를 실측과 대조한다. 리포트 공유용 백엔드와 금지 구역 공공데이터도 이 단계에서 연결한다. |

## 6. 시장 규모와 목표 지표

분모가 다른 수치의 곱셈을 제거하고 시장 추산, 지원 차량 고객층, MAU 달성 조건과 재사용률의 분모를 밝혔다.

| v1 원문 | v2 수정본 |
|---|---|
| 전기차 차박의 불안 해소: 출발 전에 아침 잔량과 충전 필요 여부를 안다. | 전기차 운전자는 출발 전에 밤사이 난방에 쓸 전력과 아침 잔량을 확인하고 충전소에 들를지 결정할 수 있다. |
| 국내 숙박 캠핑 이용자 534만 명, 차박 이용률 3.9%(2020년 기준). 이를 단순 환산하면 차박 중심 이용자는 약 20만 명 규모로 추정된다. | 2021년 차박 경험률 4%를 같은 해 12월 만 19세 이상 주민등록인구 약 4,366만 명에 적용하면 연간 경험자는 약 175만 명으로 추산된다(한국관광공사·행정안전부 자료를 활용한 자체 환산). |
| Pleos Connect는 2026년 2분기 신차부터 적용되며, 2030년까지 2천만 대 이상 적용이 목표다. 탑재 차량이 늘수록 잠재 사용자와 실측 데이터가 함께 늘어난다. | 초기 고객은 이들 중 Pleos 지원 전기차로 차박을 준비하는 운전자다. 출시 뒤 지원 차량 수, 앱 도달률과 이용률을 확인해 실제 확보 가능한 규모를 좁힌다. |
| 예상 MAU: 출시 1년차 1만 명(차박 중심 이용자의 약 5%), 3년차 10만 명. Pleos 탑재 차량 증가와 해외 확장을 반영했다. | 출시 12개월째 목표는 MAU 1만 명이다. 예를 들어 누적 도달한 지원 차량 운전자 5만 명 중 20%가 그달 스팟 조회·길안내·차박 기록을 1회 이상 쓰면 달성한다. 두 수치는 검증할 가정이다. 3년차 10만 명은 보급·유입 실적에 따라 다시 산정할 장기 목표다. |
| Retention: 차박은 주말·계절 단위 활동이라 월 단위 대신 "다음 차박 때 다시 쓰는 비율"을 본다. 목표 90일 재사용률 40%, 월간 리텐션 25%. 계절별 추천 태그, 사계절·기록왕 뱃지, 지난 방문 스팟의 새 리포트 알림이 재방문을 이끈다. | 첫 차박 기록 후 90일 안에 다시 차박을 기록한 비율 40%, 첫 이용 다음 달에 핵심 기능을 다시 쓴 비율 25%를 목표로 한다. 각 기간이 온전히 지난 이용자를 분모로 삼는다. |
| 데이터 지표: 월간 실측 리포트 수와 "참고치를 벗어난(3회 이상 기록된) 스팟 비율"을 핵심 KPI로 관리한다. | 월간 유효 리포트 수와, 스팟별로 해당 월에 유효한 전기차 기록이 3건 이상 쌓인 비율을 집계한다. 차박 전 아침 잔량 예측과 실제 종료 잔량의 차이도 %p로 측정한다. |
| 제휴 확대: 경로상 충전소 추천·예약, 근처 편의점·화장실 정보, 차박 가능 공영 주차장·오토캠핑장 예약 연계 | 충전 사업자와 협력해 충전기 가용 여부와 예약을 연결한다. 근처 편의점·화장실 정보, 차박 가능한 공영 주차장·오토캠핑장 예약으로 범위를 넓힌다. |
