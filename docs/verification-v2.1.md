# v2.1 차박 종료 잔량과 충전소 경유 검증

2026-11-13 · 신청서 v2의 린회 담당 기능에 대한 구현·검증 기록

| 항목 | 변경과 확인 결과 |
| --- | --- |
| 종료 잔량 | 차박 시작 때 8시간 뒤 예상 잔량을 보관한다. 종료 시점의 차량 잔량, 실제 체류 시간, 두 값의 차이(%p)를 보여준다. 8시간과 체류 시간이 다르면 안내한다. 예측 자료나 차량값이 없으면 해당 칸에 이유를 표시한다. |
| 배터리 보호 | 보호 기준 이하에서 공조가 켜져 있으면 정차·연결 상태를 확인하고 끄기를 요청한다. 차량의 꺼짐 상태를 수신해야 성공으로 표시한다. 요청 거절과 상태 확인 시간 초과를 구분하고, 다음 샘플에서도 조건이 맞으면 다시 시도한다. |
| 충전소 경유 | 차박지와 충전소를 함께 전달하는 새 경로, 안내 중인 차박지에 첫 경유지를 추가하는 경로를 각각 검사했다. 내비 서비스 연결 전과 권한 거절 때는 성공으로 표시하지 않는다. 경유지 추가 오류 후에는 기존 차박지를 유지한다. |

## 실행 결과

- Gradle에서 mock·Pleos 디버그 APK 빌드 성공. 단위 테스트는 mock 26건, Pleos 23건 통과했다. 공통 테스트는 양쪽에 포함된다.
- mock 테스트에서 8시간 체류, 중간에 시연 배율을 바꾼 35분 체류, 기록 미동의, 공조 끄기 거절 후 재시도, 요청 수락 뒤 꺼짐 상태 미수신을 확인했다.
- 별도 Robolectric 환경에서 Compose 화면 테스트 2건을 통과했다. 충전소를 거쳐 차박지로 가는 흐름과 공조 끄기 거절 뒤 조기 종료 화면을 확인했다. 후자의 화면에는 시작 예측 48%, 종료 잔량 10%, 차이 38%p, 체류 시간 차이 안내가 표시됐다.
- Pleos 내비 전용 테스트 4건은 실제 SDK 타입으로 앱의 요청과 콜백 처리를 검사하며, 내비 서비스 응답은 모의 처리한다.

## Pleos 기기에서 남은 확인

개발 환경에 Pleos 시스템 이미지와 연결된 차량이 없어 순정 내비 지도에서의 검증은 남아 있다. Pleos용 APK에서 아래 순서로 확인한다.

1. 안내가 없는 상태에서 충전소 경유를 선택한다. 순정 내비에 첫 경유지로 충전소, 최종 목적지로 차박지가 표시되는지 본다.
2. 같은 차박지로 직행 안내를 시작한 후 충전소를 추가한다. 최종 목적지가 유지되고 경유지가 한 번만 생기는지 본다.
3. 내비 연결 또는 권한이 없는 상태로 시도한다. 앱에 실패가 표시되고 새 경유지가 설정된 것으로 보이지 않는지 본다.
