# v2.5 시각별 기온 목업

v2.4에서는 도착을 기준으로 기온 배열의 첫 값부터 사용했다. v2.5에서는 각 스팟에 기기 현지 시각 기준의 24시간 기온을 담는다. 이 시연 데이터는 매일 반복된다.

## 데이터 수정

- 차박지와 기온은 [spots.json](../app/src/main/assets/mock/spots.json)에서 수정한다. 스팟 ID로 항목을 찾아 `hourlyTemperaturesC`의 해당 정각 값을 섭씨로 입력한다. 키는 24시간제 `HH:00`이다.
- 차박 실측 예시는 [reports.json](../app/src/main/assets/mock/reports.json)에서 관리한다. 스팟 ID와 월이 일치하는 유효 EV 기록이 2건 이상이어야 기상 잔량을 예측한다.
- 차량 프로필과 기본 세팅은 [user.json](../app/src/main/assets/mock/user.json), 스팟 프리셋은 [presets.json](../app/src/main/assets/mock/presets.json)에 있다. 경유 충전소 좌표는 [MockChargingStations.kt](../app/src/main/java/com/example/meomunjari/data/mock/MockChargingStations.kt)에 정의돼 있다.

방태산(`s-003`)의 일부 데이터는 다음과 같다.

```json
{
  "18:00": 10,
  "19:00": 9,
  "20:00": 8
}
```

한 정각의 값은 다음 정각 직전까지 유효하다. 18:45부터 19:45까지 머무르면 10°C인 첫 15분은 대기, 9°C인 다음 45분은 난방으로 예측한다. 23시 구간이 끝나면 00시 값을 이어서 쓴다.

## 앱 반영과 시연

두 플레이버 모두 APK에 포함한 JSON을 앱 시작 때 MockAssetLoader로 읽고 메모리 저장소를 만든다. 파일 편집 후 앱을 다시 빌드해 설치하고 실행한다. 앱에서 추가한 기록은 프로세스를 다시 시작하면 초기화된다. 실행 중 차량 잔량·공조를 바꾸는 가상 콘솔은 mock 플레이버에서 쓸 수 있다.

직행과 경유는 각 경로의 차박지 예상 도착 시각부터, 충전 중 화면은 지금 출발할 경우의 도착 시각부터 계산한다. 차박 중에는 실제 시작 시각과 경과 시간을 기준으로 남은 구간만 반영한다. 현재 정각 구간에서는 확인된 차량 공조 상태가 우선한다. 필요한 시간대의 기온이 누락되면 야간 잔량 예측을 보류한다. 이전 배열만 제공하는 스팟은 기존 도착 기준 계산을 사용한다.

## 검증

mock 단위 테스트 35건, Pleos 단위 테스트 31건, 별도 Robolectric 화면 테스트 2건을 통과했다. 두 APK에 패키징된 JSON에서도 스팟 9곳마다 24개의 시각 키를 확인했다.
