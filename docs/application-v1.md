# 머문자리 신청서 v1 · 변경 대상 발췌

2026-11-13 검토본. 아래 절 번호는 신청서의 항목과 대응한다.

## 2. 차 안에서 해결할 문제

왜 차 안에서 해결해야 하는가 (조사 필요)(린회)

국내 숙박 캠핑 이용자는 2020년 기준 534만 명이고, 차박 이용률은 3.9%로 별도 유형을 이룰 만큼 자리 잡았다(한국관광공사 「2020년 기준 캠핑이용자 실태조사」). 차박은 차가 곧 숙소라서, 그 밤의 온도·전력 소모·날씨를 가장 정확히 아는 것도 차다. 지금까지는 이 데이터가 차 안에서 사라졌다. 머문자리는 차량 데이터를 스팟 정보로 바꿔, 사람이 쓴 후기의 한계를 객관적인 숫자로 보완한다.

## 3. 에너지 예측과 길안내

② "내 차로 버틸 수 있나" 에너지 예측

현재 잔량, 남은 경로 거리, 해당 스팟의 실측 소모율을 합쳐 "지금 62% → 도착 60% → 아침 46% · 충전소까지 충분해요"처럼 알려 준다.

빠듯하면 "경로상 충전소에서 15분 충전 후 출발"처럼 대안을 제안한다. 실측이 없는 스팟은 “측정중”으로 표시하며 2회 이상 리포트 등록 시, 에너지 예측을 표시해준다.(린회 조사 필요)

"여기로 갈래요" 한 번으로 차량 내비 목적지를 설정한다. 주행 중(D·R단 또는 주행 속도)에는 화면을 숨기고, 남은 거리·시간·도착 시 예상 배터리 잔량을 표시해준다.

## 4. 시연 시나리오

[에너지 확인] 배터리 62%면 "아침 46% · 충분해요", 25%면 "경로상 충전소에서 15분 충전 후 출발"(주성)이 나온다.

[밤사이] 자는 동안 차가 내·외부 온도와 배터리 사용량을 기록한다. 출발 전 확인한 [에너지 확인]과 근사하게 아침에 배터리가 40%대임을 확인했다.

## 5. 구현 범위와 검증

NaviHelper SDK: requestRoute로 목적지 설정·취소, 남은 거리·시간 표시

자체 백엔드: 스팟·검색, 방문 인증, 리뷰·태그, 실측 리포트 수집·집계, 에너지 예측, 뱃지 엔진의 6개 모듈과 DB·이미지 저장소

완료: 아키텍처·화면·기능 설계. 앱 화면 9종과 시연 시나리오 전체 흐름을 로컬 목 데이터 기반으로 구현했다. 도메인 로직 단위 테스트 17건이 통과했다.

이후: 백엔드 6개 모듈을 구축해 목 데이터를 실서버로 교체하고, 금지 구역 공공데이터 연동, 위치 공개 범위 정책, 실제 일출 시각 보정 기록을 추가한다.

## 6. 시장 규모와 목표 지표

전기차 차박의 불안 해소: 출발 전에 아침 잔량과 충전 필요 여부를 안다.

국내 숙박 캠핑 이용자 534만 명, 차박 이용률 3.9%(2020년 기준). 이를 단순 환산하면 차박 중심 이용자는 약 20만 명 규모로 추정된다.

Pleos Connect는 2026년 2분기 신차부터 적용되며, 2030년까지 2천만 대 이상 적용이 목표다. 탑재 차량이 늘수록 잠재 사용자와 실측 데이터가 함께 늘어난다.

예상 MAU: 출시 1년차 1만 명(차박 중심 이용자의 약 5%), 3년차 10만 명. Pleos 탑재 차량 증가와 해외 확장을 반영했다.

Retention: 차박은 주말·계절 단위 활동이라 월 단위 대신 "다음 차박 때 다시 쓰는 비율"을 본다. 목표 90일 재사용률 40%, 월간 리텐션 25%. 계절별 추천 태그, 사계절·기록왕 뱃지, 지난 방문 스팟의 새 리포트 알림이 재방문을 이끈다.

데이터 지표: 월간 실측 리포트 수와 "참고치를 벗어난(3회 이상 기록된) 스팟 비율"을 핵심 KPI로 관리한다.

제휴 확대: 경로상 충전소 추천·예약, 근처 편의점·화장실 정보, 차박 가능 공영 주차장·오토캠핑장 예약 연계
